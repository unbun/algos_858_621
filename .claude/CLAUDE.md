# Formatting Preferences

- Present code in multi-line code blocks that are easy to copy+paste
- Present markdown tables in raw markdown format that is easy to copy+paste
- Keep comments minimal and match the existing style of the file

# Code Style Preferences

- Name classes descriptively (e.g., `NaiveBayesClassifier`, `WineDataAnalysis`), not with question numbers (avoid `Q2Analysis`, `Q3Optimization`)
- Use single class with `pipeline()` method rather than separate helper classes
- Include `verbose` flag to control print output

# Testing

- Always test code before considering it complete
- When testing, ensure the correct venv is activated (check with `which python` or run within the project's virtual environment)
